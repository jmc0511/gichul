# 출제 평가셋

바꾼 게 좋아졌는지 **숫자로 보기 위한** 장치. 프롬프트나 모델을 손대기 전에 여기서 기준선을 재고,
고친 뒤 같은 자료로 다시 돌려서 비교한다.

## 왜 필요한가

- 신고는 문항 1,901개에 14건(0.74%)이라 숫자가 움직여도 우연인지 알 수 없다
- 실제 요청의 자료는 14일 뒤 지워진다(`purge_old_requests`) → 과거 요청으로는 재현이 안 된다
- 지금까지 "좋아진 것 같다"는 느낌 말고는 판단 근거가 없었다

신고 사유 상위 두 가지가 **"자료에 없는 내용"**과 **"정답이 틀려요"**라서, 채점도 그 둘을 겨냥한다.

## 한 번 돌리기

```sh
node eval/extract.mjs 운영체제_3장 ~/Downloads/os3.pdf   # 케이스 만들기 (PDF → material.txt)
# eval/cases/운영체제_3장/instructions.txt 에서 문항 수·유형을 자료에 맞게 고친다
node eval/run.mjs                                        # 출제 (케이스 전부)
node eval/grade.mjs                                      # 채점 + 점수표
```

`CLAUDE_MODEL` 로 모델을 고른다. 기본값은 NAS(`nas/docker-compose.yml`)와 같은 `claude-opus-5-5`.

```sh
CLAUDE_MODEL= node eval/run.mjs          # --model 없이 CLI 기본 모델로
```

> `claude-opus-5-5` 는 **Claude Code 2.1.280 이상**이라야 쓸 수 있다. 그보다 낮으면
> `does not support this model` 로 실패한다 → `claude update`.

## 케이스 만들기

`eval/cases/<이름>/`

| 파일 | 설명 |
|---|---|
| `material.txt` | 공부자료 원문. 사이트가 보내는 형식(`===== 자료: 이름 =====` / `[p.1]`) 그대로 |
| `instructions.txt` | 출제 조건. 사이트의 `buildInstructions()` 결과. `eval/instructions-template.txt` 를 고쳐 쓰면 된다 |
| `images/01.jpg …` | (선택) 자료 속 그림. 파일 이름 숫자 = 이미지 번호 |
| `images/labels.json` | (선택) `{"1":"이미지 #1 (강의노트.pdf p.3)"}` |

만드는 방법은 둘:

1. **`extract.mjs`** — 사이트와 같은 pdf.js 같은 버전으로 글자를 뽑는다. 그림은 안 뽑는다.
2. **실제 요청에서 가져오기** — 사이트에서 한 번 보낸 뒤 14일 안에 `requests` 표의
   `material`·`instructions`·`images` 를 그대로 복사. 그림까지 똑같아서 가장 정확하다.

좋은 평가셋은 **실제로 사람들이 올리는 자료**를 닮아야 한다. 글자 많은 PDF, 그림 위주 슬라이드,
스캔·필기 사진, 긴 자료(100쪽 이상)를 섞어 5~6개면 충분하다.

## 채점이 세는 것

**기계 점검** (모델 없이): 문항 수, 객관식 선지 5개, 정답 번호 범위, 같은 선지, 동그라미 숫자 직접 쓰기,
`source` 표기, 같은 문제 중복, 지문(`passage_id`)이 떨어져 있는지.

**모델 점검**: 정답과 해설을 **가린** 문항을 자료와 함께 다시 주고 직접 풀게 한 뒤,
- `정답불일치` — 객관식·OX에서 채점자가 푼 답이 시험지 정답과 다름
- `자료근거없음` — 자료에 없는 내용을 묻고 있음
- `정답다수/없음` — 객관식에서 정답이 될 선지가 하나가 아님
- `애매` — 조건이 모자라 답이 갈림

단답·서술형은 글자 대조로 맞다·틀리다를 가릴 수 없어 **정답 대조에서 뺀다**(점수표의 `정답대조` 열이 실제로 대조한 문항 수).

## 믿을 수 있는 범위

채점도 출제와 **같은 모델**이라 같은 착각은 같이 한다. 분명한 오류(정답이 둘, 자료에 없는 사실)는 잡지만
미묘한 품질은 못 잡는다. 숫자가 줄었다고 품질이 좋아졌다고 단정하지 말고, 바뀐 문항을 눈으로 한 번 볼 것.
케이스가 적으면 1~2건 차이는 우연이다.

## 올리지 않는 것

`eval/cases/` 와 `eval/results/` 는 `.gitignore` 에 있다. 저장소가 공개라서
**남의 강의자료와 개인정보가 들어간 파일을 올리면 안 된다.** 자료는 이 컴퓨터에만 둔다.
