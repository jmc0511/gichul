## 2. 애플 로그인 (앱 스토어 심사 4.8 때문에 꼭 필요)

구글 로그인이 있는 앱은 애플 로그인도 있어야 합니다. 사이트는 **앱 안에서만** 애플 로그인
버튼을 보여 주고, 같은 `oauth` 핸들러로 Supabase 애플 로그인을 합니다.

### 2-1. 애플 개발자 사이트에서 값 4개 만들기

developer.apple.com → Certificates, Identifiers & Profiles

1. **App ID** (Identifiers → App IDs → `site.gichul.app`, Description 은 `Gichuri`)
   - Capabilities 에서 **Sign In with Apple** 체크 → Save
   - (**Push Notifications** 도 같이 체크해 두세요. 3번에서 씁니다)
2. **Services ID** (Identifiers → + → Services IDs)
   - Description: `Gichuri Sign In`, Identifier: **`site.gichul.app.signin`** ← 이게 Supabase 의 Client ID
   - ⚠ **Description 칸은 영문·숫자·공백만 됩니다.** 한글이나 점·하이픈을 넣으면
     "Invalid description" 이라고 거절합니다 (Identifier 칸은 점을 써도 됩니다)
   - 만든 뒤 다시 열어 **Sign In with Apple** 체크 → Configure
     - Primary App ID: `site.gichul.app`
     - Domains and Subdomains: `cjqhbckclrteazlwjruo.supabase.co`
     - Return URLs: `https://cjqhbckclrteazlwjruo.supabase.co/auth/v1/callback`
     - Save → Continue → Save
3. **Key** (Keys → +)
   - Key Name: `Gichuri Sign In Key` (여기도 영문·숫자·공백만), **Sign in with Apple** 체크 → Configure → Primary App ID `site.gichul.app`
   - Register → **.p8 파일 내려받기 (딱 한 번만 받을 수 있음)**, 화면의 **Key ID** 적어 두기
4. **Team ID**: 오른쪽 위 계정 이름 아래 10자리 (Membership 에서도 보임)
   — **출시할 계정의 Team ID** 여야 하고, Xcode 프로젝트에도 같은 값이 들어가 있어야 합니다

정리하면: `Services ID = site.gichul.app.signin`, `Key ID`, `Team ID`, `.p8 파일`

### 2-2. Supabase 에 넣을 비밀 글자 만들기

애플은 비밀번호 대신 **6개월짜리 서명 글자(JWT)** 를 받습니다. 이 컴퓨터에서 만듭니다.

```bash
cd app/gichuri
node tool/apple-client-secret.mjs \
  --p8 ~/Downloads/AuthKey_<KeyID>.p8 \
  --team <TeamID> --key <KeyID> --services site.gichul.app.signin
```

나온 긴 글자를 복사합니다. (.p8 파일은 안전한 곳에 보관 — 6개월 뒤 다시 만들 때 필요)

### 2-3. Supabase 에 넣기

Authentication → Providers → **Apple** → Enable

| 칸 | 넣을 값 |
|---|---|
| Client IDs | `site.gichul.app.signin,site.gichul.app` |
| Secret Key (for OAuth) | 2-2 에서 나온 긴 글자 |

> Client IDs 에 번들 ID(`site.gichul.app`)도 같이 넣어 두면, 나중에 네이티브 애플 로그인으로
> 바꿔도 그대로 동작합니다.

**달력에 적어 두기: 6개월 뒤 2-2 를 다시 해서 Secret Key 교체** (안 하면 애플 로그인이 멈춥니다)

## 3. 시험지 완성 알림 (FCM)

### 3-1. Firebase 프로젝트

1. console.firebase.google.com → 프로젝트 만들기 (이름 예: `gichuri`) · 애널리틱스는 꺼도 됩니다
2. **iOS 앱 추가**: 번들 ID `site.gichul.app` → `GoogleService-Info.plist` 내려받기
   ```bash
   cp ~/Downloads/GoogleService-Info.plist app/gichuri/ios/Runner/
   cd app/gichuri && ruby tool/xcode-setup.rb     # Xcode 프로젝트에 넣어 줌
   ```
3. **안드로이드 앱 추가**: 패키지 이름 `site.gichul.app` → `google-services.json` 내려받기
   ```bash
   cp ~/Downloads/google-services.json app/gichuri/android/app/
   ```
4. **APNs 키** (아이폰 알림에 필요)
   - developer.apple.com → Keys → + → Key Name `Gichuri APNs Key` →
     **Apple Push Notifications service (APNs)** 체크 → .p8 내려받기, Key ID 적기
   - Firebase → 프로젝트 설정 → **클라우드 메시징** → Apple 앱 구성 → **APNs 인증 키 업로드**
     (.p8 + Key ID + Team ID)
   - 로그인 키와 APNs 키는 **다른 키**입니다. 둘 다 만들어야 합니다.
5. **서비스 계정 키** (서버가 알림을 보낼 때 씀)
   - Firebase → 프로젝트 설정 → **서비스 계정** → 새 비공개 키 생성 → JSON 내려받기 (3-3 에서 씀)

### 3-2. Xcode 에서 한 번 확인

`app/gichuri/ios/Runner.xcworkspace` 를 열고 Runner → Signing & Capabilities 에서
**Push Notifications** 가 보이면 됩니다 (안 보이면 + Capability → Push Notifications).

### 3-3. 알림 보내는 함수 올리기 (Supabase)

1. 대시보드 → **Edge Functions** → Deploy a new function → 이름 **`push-exam-ready`**
   → 편집기에 `app/gichuri/server/push-exam-ready/index.ts` 내용을 그대로 붙여넣고 Deploy
   (CLI 를 쓴다면 `supabase functions deploy push-exam-ready`)
2. 같은 화면의 **Secrets** 에 두 개 넣기
   - `FCM_SERVICE_ACCOUNT` : 3-1-5 에서 받은 JSON **파일 내용 통째로**
   - `PUSH_SECRET` : 아무 긴 글자 (예: `openssl rand -hex 24` 결과)
3. **Database → Webhooks → Create a new hook**
   - Name: `exam-ready-push`
   - Table: `public.requests` · Events: **Update** 만 체크
   - Type: **HTTP Request** · Method: `POST`
   - URL: `https://cjqhbckclrteazlwjruo.supabase.co/functions/v1/push-exam-ready`
   - HTTP Headers:
     - `Authorization` : `Bearer <service_role 키>`
     - `x-push-secret` : 위에서 정한 `PUSH_SECRET`
     - `Content-Type` : `application/json`
   - Create

### 3-4. 잘 되는지 보기

1. 실기기(시뮬레이터는 알림을 못 받습니다)에 앱을 깔고 출제 요청을 보냅니다
   → "시험지가 완성되면 알려 드릴까요?" 가 뜨면 **알림 받기**
2. Supabase → Table Editor → `push_devices` 에 줄이 생겼는지, `push_watch` 에 그 요청이 있는지 확인
3. 앱을 홈 버튼으로 내려놓고 1~2분 기다리면 "시험지가 완성됐어요" 알림이 옵니다
4. 안 오면 Edge Functions → push-exam-ready → Logs 를 봅니다

## 4. 안드로이드 출시 서명 키 (Play 올릴 때)

```bash
keytool -genkey -v -keystore ~/gichuri-release.jks -keyalg RSA -keysize 2048 \
  -validity 10000 -alias gichuri
```

비밀번호는 직접 정하고 **안전한 곳에 보관**하세요 (잃어버리면 같은 앱을 업데이트할 수 없습니다).
그다음 `app/gichuri/android/key.properties` 를 만듭니다 (이 파일은 저장소에 안 올라갑니다):

```properties
storeFile=/Users/pure/gichuri-release.jks
storePassword=정한_비밀번호
keyAlias=gichuri
keyPassword=정한_비밀번호
```
