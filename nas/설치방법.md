# NAS(헤놀로지/시놀로지 DSM 7.2+)에 출제 처리기 설치

1. PC 터미널에서 `claude setup-token` → 브라우저 로그인 → 나온 `sk-ant-oat…` 토큰 복사
2. `.env` 채우기: CLAUDE_CODE_OAUTH_TOKEN, SUPABASE_URL, SUPABASE_SECRET (secret.json 과 같은 값)
3. File Station → `docker` 공유폴더 아래 `gichul` 폴더 만들고, 이 nas 폴더의 파일 전부 업로드
   (Dockerfile, docker-compose.yml, .env, package.json, queue.mjs, runner.mjs, PROMPT-exam.md, PROMPT-summary.md, PROMPT-explain.md, PROMPT-ink.md)
   코드는 이미지에 굽지 않고 이 폴더를 `/app/src` 로 연결해서 쓴다 (docker-compose.yml 의 volumes)
4. Container Manager → 프로젝트 → 생성
   - 프로젝트 이름: gichul / 경로: /docker/gichul / 소스: 기존 docker-compose.yml 사용
   - 다음 → 완료 (이미지 빌드 후 자동 시작)
5. Container Manager → 컨테이너 → gichul-worker → 로그 에서 "대기열 감시 시작" 확인

DSM 7.1 이하(프로젝트 메뉴 없음): SSH 접속 후
`cd /volume1/docker/gichul && sudo docker-compose up -d --build`

## 코드를 고쳤을 때 (대부분의 경우)

코드(`*.mjs`, `PROMPT-*.md`)는 이미지 안에 들어 있지 않고 폴더째 연결돼 있다. 그래서:

1. File Station 에서 바뀐 파일만 덮어쓰기
2. Container Manager → 컨테이너 → `gichul-worker` → **다시 시작**
3. 로그 첫 줄 "처리기 시작 (실시간 알림 …)" 확인

**이미지를 다시 만들 필요도, 컨테이너를 지울 필요도 없다.** 30초면 끝난다.

## 이미지를 다시 만들어야 할 때 (드묾)

`package.json` 이나 `Dockerfile` 이 바뀌었을 때만:
1. 파일 덮어쓰기 → 프로젝트 정지
2. 컨테이너 탭에서 gichul-worker 삭제, 이미지 탭에서 gichul-gichul-worker 삭제
3. 프로젝트 → 작업 → 빌드

## 재시작 전에 볼 것

출제가 돌고 있으면 그 요청은 끊긴다(3분 뒤 자동으로 다시 대기열로 간다).
`requests` 에 pending·working 이 있는지 보고 하는 게 안전하다.
